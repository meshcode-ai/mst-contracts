# MST contracts and pinned protocol sources

Public contract workspace for the MST intelligence token, MeshPet NFTs, AMM, and perpetuals research/test integration. The landing website and desktop application are maintained separately.

No new AMM, perpetuals, NFT market, or oracle Solidity engine is authored here. `src/MeshToken.sol` and `src/Meshling.sol` reproduce the existing MeshCode GIWA contracts unchanged. Source hashes and exact upstream commits are in [source-lock.json](source-lock.json).

## Reproduce local validation

Install Bun 1.4.0 and initialize the pinned submodules:

```sh
git submodule update --init --recursive
bun install --frozen-lockfile
bun run test
```

`test` compiles the unchanged legacy contracts and tests mint/burn roles, supply, NFT enumeration, metadata, royalties, and transfer authority on an isolated Anvil instance. Test accounts are local unlocked fixtures.

Build the original NFT protocols before their integration tests:

```sh
cd upstream/seaport
FOUNDRY_PROFILE=optimized ../../node_modules/.bin/forge build contracts/Seaport.sol lib/seaport-core/src/conduit/ConduitController.sol
cd ../seadrop
../../node_modules/.bin/forge build src/SeaDrop.sol src/ERC721SeaDrop.sol
cd ../..
bun run test:nft
```

The NFT integration test uses real upstream contracts: native-ETH public mint, wrong-payment/wallet-cap rejection, an MST fixed-price Seaport sale, duplicate fulfillment rejection, and onchain cancellation. SeaDrop v1 public mint uses ETH, not MST. The original ERC721SeaDrop does not implement ERC-2981; the legacy Meshling contract does. Any royalties must be expressed by the settlement order and are not an automatic token burn.

The [AMM integration guide](AMM.md) records exact source/SDK pins, original-contract build commands, wallet call flow and test inputs. For real MST/WETH swap and full-range LP tests, run `bun run build:amm` followed by `bun run test:amm`. A separate `bun run deploy:amm:local` adds the pool to the existing local token/NFT deployment.

AMM and perpetuals also retain their original toolchain tests:

```sh
cd upstream/v4-core
../../node_modules/.bin/forge test --match-path 'test/PoolManager*.t.sol' --match-test 'test_(initialize|swap|addLiquidity_succeedsIfInitialized|removeLiquidity_succeedsIfInitialized)' --fuzz-runs 32 --threads 2
cd ../gmx
SKIP_YARN_COREPACK_CHECK=1 bunx yarn@1.22.22 install --frozen-lockfile --ignore-scripts --ignore-engines --non-interactive
node node_modules/hardhat/internal/cli/cli.js test test/exchange/LiquidationOrder.ts test/guardian/testLiquidation.ts test/oracle/Oracle.ts
```

GMX's existing oracle signing helpers and liquidation contracts are used. Its test chain is Hardhat 31337 without a live-chain fork. The displayed price scenario in an application is separate from execution of this engine test. Foundry gas snapshots may be regenerated by upstream tests; these are not protocol source modifications.

The controlled oracle driver [test/demo-perps.cts](test/demo-perps.cts) uses those same original helpers and contracts. From `upstream/gmx`, run:

```sh
node node_modules/hardhat/internal/cli/cli.js test --no-compile --network hardhat ../../test/demo-perps.cts
```

It checks normal-price rejection, a $4,000 long liquidation, a $6,000 short liquidation, rejection of duplicate liquidation, and the actual oracle's stale-price rejection. Set `MST_DEMO_SCENARIO` to `normal`, `long-crash`, `short-squeeze`, or `stale` to run one scenario. Each starts a fresh fixture. The `.cts` extension is intentional for GMX's CommonJS Hardhat toolchain inside this ESM workspace. No contract logic is modified.

`bun run deploy:local` deploys only to `127.0.0.1:8547`, verifies chain 31337, and uses unlocked test accounts. It has no private-key argument. It writes `deployments/local.json`; it can optionally update a sibling local application's address registry. No GIWA deployment is implied.

## Scope and provenance

MST has role-controlled elastic supply. The original `computeUnits` event field records offchain metering; it does not prove GPU work or guarantee token value. Source comments are preserved for reproducibility and do not override the implemented behavior.

Upstream audit records are linked in their own repositories. A published fork, local test, or tagged library is not an independent audit of a new deployment. GIWA contract addresses, oracle feeds, keeper roles, production liquidity, and deployment verification must be recorded separately. No private RPC credentials or signing keys belong in this repository.
